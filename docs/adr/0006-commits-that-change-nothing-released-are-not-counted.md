# 0006. リリースされるものを変えないコミットは数えない

- Date: 2026-11-01
- Status: Accepted
- 改めるもの: ADR 0002 の「離れ具合」

## Context

ADR 0002 では、最新のリリースのタグからデフォルトブランチまでのコミットを、マージコミットを
除いてすべて数えていた。実際に数えてみると、人のコミットのほとんどは CI のワークフロー・
Renovate の設定・ADR・README を変えたもので、リリースされるもの（イメージやバイナリ）を
変えていなかった。数字が溜まり具合を実際より多く見せ、手でリリースすべきリポジトリが
見分けにくい。

週次の自動リリース（`plan-release.sh`）は、すでにリリースに入らないパスを `RELEASE_IGNORE` で
除いて判断している。リポジトリごとに、配布物に入るファイルだけを見るように直したスクリプトもある。

リポジトリごとの release スクリプトを読み解いて除外を合わせる仕組みは、煩雑なので作らない。
全リポジトリ共通の除外を一つ持つ。

## Decision

### 数えるコミット

`commitsSinceRelease` と `nonRenovateCommitsSinceRelease`（とそれぞれのメトリクス）は、
次のコミットを数えない。

- マージコミット（ADR 0002 のとおり）
- 変えたファイルがすべて除外のパターンに合うコミット

除外に合わないファイルを一つでも変えたコミットは、ほかに除外のファイルを含んでいても数える。

### 除外のパターン

設定の `releaseIgnore`（文字列の一覧、任意）に書く。書けば既定を置き換え、空の一覧を書けば
何も除外しない（ADR 0002 の数え方に戻る）。

書き方は gitignore に寄せた小さな部分集合で、正規表現は使わない。どの形も `*` などのワイルドカードが
使える（Go の `path.Match`）。

| 形 | 合うもの | 例 |
|---|---|---|
| `/` で終わる | リポジトリ直下のそのディレクトリの下すべて | `.github/`・`docs/` |
| `/` を含まない | どの深さでも、その名前のファイルかディレクトリ | `*.md`・`LICENSE*` |
| それ以外 | 直下からのパス全体 | `deploy/*/README.txt` |

空のパターンや、ワイルドカードの書き方を誤ったパターンがあれば起動しない。

既定は次のとおり。

| パターン | 理由 |
|---|---|
| `.github/`・`.gitlab/` | CI と、そこに置いた Renovate の設定 |
| `.claude/` | エージェントの設定 |
| `docs/` | ADR などの文書 |
| `renovate.json`・`renovate.json5`・`.renovaterc`・`.renovaterc.json`・`.renovaterc.json5` | ADR 0002 で追跡の判定に使う Renovate の設定 |
| `*.md` | README・CLAUDE.md・AGENTS.md・Wiki の本文 |
| `LICENSE*`・`.gitignore`・`.gitattributes`・`.editorconfig` | リポジトリの付属物 |
| `.golangci.yml`・`.golangci.yaml` | lint の設定 |

`plan-release.sh` の `RELEASE_IGNORE` の既定はすべてこの中に入る。

既定に入れないもの: `Makefile`・`scripts/`・`.dockerignore`。配布物に効くリポジトリがある。
迷うものは数える側に倒す。数え過ぎより数え漏れのほうが、リリースを忘れる害が大きい。

### 調べ方

1. compare の応答には、比較全体で変わったファイルの一覧が付く（1 ページ目にだけ付き、
   GitHub は 300 件までしか出さない）。一覧が 300 件未満で、すべて除外に合うなら、
   どのコミットもリリースされるものを変えていない。コミットを一つずつ調べずに 0 とする。
   300 件ちょうどなら、切り詰められているかもしれないので使わない
2. そうでなければ、マージでないコミットごとにコミットの API を 1 回呼び、変えたファイルを調べる
3. コミットの中身は変わらないので、判定の結果をリポジトリと SHA ごとにメモリに持ち、
   次の集計では呼ばない。持つのはプロセスが生きている間だけで、その回の集計に出てこなかった
   コミットの結果は捨てる

1 は `plan-release.sh` の「リリースされるものを何も変えていない」と同じ判定である。
あるコミットが入れた変更を別のコミットが戻したときは、どちらも数えないことになる。
リリースすべき差が残っていないので、これでよい。

コミットのファイルを読めなかったリポジトリは、ADR 0002 の「測れなかったリポジトリ」として扱う。
コミット数と compare の URL は持たない（null になる）。

## Consequences

- 人の CI や文書だけの変更では数が増えなくなり、手でリリースすべきリポジトリが目立つ
- HTTP API とメトリクスの名前（ADR 0004）は変わらない。意味が「リリースされるものを変えた
  コミットの数」に変わる
- 1 回の集計で、マージでないコミットの数だけ GitHub の呼び出しが増える。2026-11-01 の実測では
  起動直後の集計で約 30 回増えた（それまでの集計は 100 回前後）。2 回目からはキャッシュにより、
  新しいコミットの分だけになる。250 コミット溜まったリポジトリがあっても、毎時 5,000 回の上限には遠い
- 除外を変えるには設定を変えて Pod を作り直す。キャッシュはプロセスとともに消えるので、
  古い除外で判定した結果が残ることはない
- リポジトリごとの release スクリプトとは、除外が完全には揃わない。リポジトリ固有の
  配布物の外のファイル（たとえば CI 用のスクリプトを `scripts/` に置いたもの）は数に残る
