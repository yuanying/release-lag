# 0001. gated の内側で動く常駐の集計サーバー

- Date: 2026-10-29
- Status: Accepted

## Context

yuanying のリポジトリの多くは Renovate で依存を更新し、patch などは自動でマージされる。
週次の自動リリースは「前回のタグ以降のコミットが Renovate のものだけなら」パッチ版を打つ。
人のコミットが一つでも混ざると自動では出ず、手で版を切るまで、デフォルトブランチは
リリースから離れたままになる。

どのリポジトリがどれだけ離れているか、何日リリースしていないかを一覧で見たい。後で個人
アシスタント（なつみ）にも同じものを見せたいので、人が見る画面とは別に、機械が読める口も要る。

設計は 2026-10-28〜29 に grill-me で 1 問ずつ決めた。

## Decision

- **作る範囲**: JSON の API と、それを表で見せる HTML 1 枚。同じサーバーが `/` で HTML を返し、
  HTML は API を読んで描く。HTML のために別の描画経路を持たない
- **動かす場所**: fraction クラスタ。manifest は fleet-infra の `apps/release-lag` に直接書く
  （release-lag 側に `config/` を持たせて取り込む形にはしない。RBAC の無い小さなアプリで、
  取り込みの仕組みが割に合わないため）
- **集計の時機**: 一定の間隔（既定 1 時間、設定できる）で集計し、結果をメモリに持つ。
  起動した直後にも 1 回集計する。`POST /api/refresh` で手で作り直せる。応答には集計した時刻を
  含める。永続化はしない。Pod が作り直されたら次の集計までの数秒が空になるだけである
- **同時に走る集計は一つ**: 集計中に作り直しを頼まれたら、走っている集計を待ってから改めて集計する
- **認証はアプリに持たせない**: gated の Ingress（ingressClassName `gated`）で出し、NetworkRole /
  NetworkRoleBinding で GitHub ログインの `github:yuanying` だけを通す。後の別タスクで gated が
  ServiceAccount（TokenReview）の主体を受けられるようになったら、なつみなどはその token で通す。
  アプリには認証のコードを入れない
- **private リポジトリも含める**。画面と API は gated の内側にしか出ないので、名前が見えてよい
- **言語**: Go。標準ライブラリ中心（`net/http`・`embed` で埋め込んだ HTML・`log/slog`）。
  GitHub API は読む口が少ないので、クライアントのライブラリを使わず小さく自前で書く。
  メトリクスだけ Prometheus の公式クライアントを使う

## Consequences

- アプリは状態をメモリにしか持たないので、Deployment は 1 レプリカで足り、書き込み領域も要らない
  （readOnlyRootFilesystem で動く）
- gated を通らずにサービスへ届く経路（同じクラスタの Pod など）からは誰でも読める。読めるのは
  リポジトリの名前とタグとコミット数で、書き込みの操作は集計のやり直しだけである
- `POST /api/refresh` は CSRF の対策を持たない。他サイトから叩かれても集計がやり直されるだけで、
  GitHub の rate limit を少し使う以上の害は無い
- なつみとの繋ぎこみは API の口を用意するところまでで、今回は手を付けない
